# Post-freeze polish: planner no-preference semantics + Gear Readiness label

Status: PASS (Targeted QA 2026-10-19, 11/11). Not a feature; no FEATURE-011; freeze active; not committed.

## Root cause (verified in source)
`ConversationPlannerService`: `difficulty == null` meant both "never answered" and "answered any"; `isReady()` required `difficulty != null`; `clarificationFor()` asked difficulty whenever it was null; the extraction schema had no way to express "no preference" for difficulty (only scenery's empty list); the extractor never saw the pending question, so a bare "any" carried no meaning → the same question forever.

## Change (backend, recommendation-service only; user-approved)
- `PlanningContext` + `openPreferences: PlanningPreference[]` (null → [], de-duplicated, enum order) and `lastAsked: PlanningPreference | null`; new enum `PlanningPreference { DIFFICULTY, SCENERY, TRIP_LENGTH }`. Optional on requests (old contexts accepted), always on responses; unknown enum → 400.
- Extraction: structured output gains `openPreferences` and an internal `generallyFlexible` flag (not in the context); the system prompt teaches no-preference semantics (any, anything, no preference, doesn't matter, whatever, I'm flexible, either is fine, any difficulty, …); the user prompt carries the pending question's dimension as a fixed server-side description before the untrusted `<user_message>`; the prompt guard still runs first. `/api/recommendations/query` ignores the new outputs.
- Merge: values from one message all apply; a named open dimension becomes open and loses its value (value in the same message wins); general flexibility opens only dimensions without a value and clears nothing; a valued dimension leaves `openPreferences`; ask-once: `lastAsked` still unresolved after the reply → open.
- Readiness: difficulty resolved (value or open) AND trip group resolved (duration/distance/elevation value, non-empty scenery, or TRIP_LENGTH/SCENERY open). Otherwise one question, difficulty first then trip length; `lastAsked` set; null when ready. Acknowledgement prefix when something opened ("Got it — I'll keep the difficulty open." / "Sounds good. I'll keep that flexible."); questions add ", or should I keep that open too?" once anything is open.
- Recommendation algorithm, scoring weights, hard filters, weather shortlist, synthetic trails: unchanged.
- Files: `dto/PlanningPreference.java` (new), `dto/PlanningContext.java`, `dto/PlanningContextDelta.java`, `ai/IntentExtractionOutput.java`, `ai/IntentPromptBuilder.java`, `ai/IntentExtractor.java`, `ai/OpenAiIntentExtractor.java`, `service/RecommendationIntentService.java`, `service/ConversationPlannerService.java`.
- Tests: ConversationPlannerServiceTest 21 (rewritten; A–H, ask-once, overrides, old shape), PlannerControllerTest 6 (contract), IntentPromptBuilderTest 5 (new), OpenAiIntentExtractorTest 10, RecommendationIntentServiceTest 4; dates → `LocalDate.now().plusDays(1)` in PlannerControllerTest, RecommendationControllerTest, ConversationPlannerServiceTest. recommendation-service: **80/80 PASS** (was 51).
